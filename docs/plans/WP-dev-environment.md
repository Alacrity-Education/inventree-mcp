# WP-dev: docker-based development and test environment

Goal: one command brings up a disposable InvenTree (stable image, the plugin installed editable from this checkout, demo data loaded, SSO against a disposable Authentik), and one command runs the plugin test suite inside it. Everything lives in `dev/` in this repo. Nothing here touches the user's other containers (an unrelated `alacrity-pg` already listens on host port 5432, so **publish nothing on 5432**).

Read first: `docs/plans/00-overview.md`, upstream `.github/workflows/ci.yaml` and `run_tests.sh` (how tests run against the stable image), `/home/alex.lucaci/Projects/inventree/InvenTree/contrib/container/{docker-compose.yml,.env,Caddyfile,init.sh}` (reference stack), `/home/alex.lucaci/Projects/inventree/KINA/scripts/e2e/authentik/{compose.yaml,bootstrap.py,kina_authentik_e2e.py}` (Authentik bootstrap to adapt).

## Services (`compose.yaml`)

- `db`: `postgres:17-alpine`, no published port, volume `pgdata`, healthcheck.
- `cache`: `redis:7-alpine`, `--save "" --appendonly no`.
- `mailpit`: `axllent/mailpit`, publish `127.0.0.1:8025:8025` (web UI); SMTP on 1025 internal. Needed because InvenTree refuses SSO self-registration unless an e-mail host is configured.
- `inventree-server`: `inventree/inventree:${INVENTREE_TAG:-1.5.7}` (pin a 1.5.x tag; `stable` as documented override). `env_file: inventree.env`. Volumes: `./data:/home/inventree/data`, `..:/home/inventree/plugins/inventree-mcp` (the repo root, read-write so an editable install works), `../../demo-dataset:/home/inventree/demo:ro`. Publish `127.0.0.1:8000:8000` (direct gunicorn, handy for curl). Healthcheck like the reference compose. Run as root (`user: root`) like the upstream CI does, so `pip install -e` into the image's site-packages works; if the official `init.sh` already installs `plugins.txt` via `invoke update`, rely on it, otherwise add a tiny entrypoint wrapper `dev/entrypoint.sh` that installs the plugin and `django_slowtests==1.1.1` then execs the original `init.sh`. Document which path you took and why.
- `inventree-worker`: same image, `command: invoke worker`, same volumes and env, depends on server healthy.
- `proxy`: `caddy:alpine` with `dev/Caddyfile`, publish `127.0.0.1:8080:80`, volumes for `data/static`, `data/media`. This is the URL everybody uses: `http://localhost:8080`.
- `authentik-db`, `authentik-server`, `authentik-worker`: copy KINA's service definitions (Authentik 2026.8.x, `postgres:16-alpine`). Publish Authentik on `0.0.0.0:${AUTHENTIK_PORT:-19000}:9000` (all interfaces, see reachability below).

InvenTree environment (`inventree.env`), on top of the reference `.env`: `INVENTREE_SITE_URL=http://localhost:8080`, the three `INVENTREE_USE_X_FORWARDED_*=True`, `INVENTREE_PLUGINS_ENABLED=True`, `INVENTREE_PLUGINS_MANDATORY=inventree-mcp` (no need to toggle it in the UI), `INVENTREE_AUTO_UPDATE=True`, `INVENTREE_DEBUG=True` (tracebacks; note that DEBUG also opens CORS to all origins, acceptable in dev), `INVENTREE_LOG_LEVEL=INFO`, `INVENTREE_ADMIN_USER=admin`, `INVENTREE_ADMIN_PASSWORD=admin`, `INVENTREE_ADMIN_EMAIL=admin@example.test` (auto-creates the superuser), `INVENTREE_EMAIL_HOST=mailpit`, `INVENTREE_EMAIL_PORT=1025`, `INVENTREE_EMAIL_SENDER=inventree@example.test`, `INVENTREE_CORS_ORIGIN_WHITELIST=https://claude.ai,https://claude.com`, `INVENTREE_TIMEZONE=Europe/Bucharest`, DB and cache settings pointing at `db`/`cache`.

## Authentik reachability (the one tricky part)

The browser on the host and the InvenTree container must reach Authentik under **one and the same URL**, because the OIDC issuer and every endpoint in the discovery document are derived from it. Use the hostname `authentik.localtest.me` (public DNS maps `*.localtest.me` to 127.0.0.1) on port 19000:
- host browser: `http://authentik.localtest.me:19000` resolves to 127.0.0.1 where the port is published;
- containers: add `extra_hosts: ["authentik.localtest.me:host-gateway"]` to `inventree-server` and `inventree-worker`, which maps the name to the docker host; the port is published on all interfaces so the host-gateway address reaches it.
Verify both with `getent hosts authentik.localtest.me` on the host and `docker compose exec inventree-server getent hosts authentik.localtest.me`. If the host cannot resolve `localtest.me` (no DNS), the README must say to add `127.0.0.1 authentik.localtest.me` to `/etc/hosts` and `up.sh` must detect and print that instruction.

Authentik bootstrap (adapt KINA's `bootstrap.py`; keep its `Api`, `wait_ready`, `get_or_create` helpers, change only the data):
- groups: `inventree-users`, `inventree-mcp`, `inventree-guests`;
- users (password printed in README, fixed for dev): `e2e-member` (users + mcp), `e2e-interactive` (users only), `e2e-guest` (guests only), `e2e-nonmember` (no group);
- scope mapping `groups` (same expression as KINA);
- provider "InvenTree dev": confidential, `authorization_code` + `refresh_token`, strict redirect URI `http://localhost:8080/accounts/authentik/login/callback/` (allauth OIDC callback with InvenTree's empty URL prefix and provider id `authentik`), RS256 signing key, scopes `openid email profile offline_access groups`, implicit consent, refresh token validity 30 days, access token 10 minutes;
- application slug `inventree`, bindings for `inventree-users`, `inventree-mcp`, `inventree-guests` (policy engine "any"), so `e2e-nonmember` is refused by Authentik itself and `e2e-guest` passes Authentik but has no InvenTree role.
- Output JSON to `dev/authentik/.bootstrap.json` (git-ignored) and stdout.

InvenTree SSO config (`data/config.yaml`, generated from the template with the bootstrap output):

```yaml
social_providers:
  openid_connect:
    SCOPE: [openid, profile, email, offline_access]
    APPS:
      - provider_id: authentik
        name: Authentik
        client_id: <from bootstrap>
        secret: <from bootstrap>
        settings:
          server_url: http://authentik.localtest.me:19000/application/o/inventree/
```

`configure_inventree.py` (idempotent, run via `docker compose exec inventree-server python src/backend/InvenTree/manage.py shell < dev/configure_inventree.py` or the equivalent path inside the container):
- global settings via `common.models.InvenTreeSetting.set_setting(key, value, None)`: `ENABLE_PLUGINS_URL`, `ENABLE_PLUGINS_APP`, `ENABLE_PLUGINS_SCHEDULE`, `ENABLE_PLUGINS_INTERFACE` = True; `LOGIN_ENABLE_SSO`, `LOGIN_ENABLE_SSO_REG`, `LOGIN_ENABLE_SSO_GROUP_SYNC`, `LOGIN_SIGNUP_SSO_AUTO` = True; `SSO_GROUP_KEY=groups`; `SSO_GROUP_MAP` = JSON `{"inventree-users": "Users", "inventree-mcp": "MCP Users"}`; `SSO_REMOVE_GROUPS=True`.
- groups `Users` (every `RuleSet` row `can_view=True`, nothing else) and `MCP Users` (no roles; WP3 fills the MCP ruleset). Core creates the `RuleSet` rows for a new group automatically; just set the flags.
- print a short summary.

Demo data: after migrations, `invoke import-records -f /home/inventree/demo/inventree_data.json` (confirm the exact task name with `invoke --list` inside the container; it may live under the `dev` collection) and copy `demo/media/*` into `data/media/`. Only on first bring-up (marker file `data/.demo-loaded`).

## `up.sh` sequence

1. Create `dev/.env` if missing (random `PG_PASS`, `AUTHENTIK_SECRET_KEY`, `AUTHENTIK_BOOTSTRAP_PASSWORD`, `AUTHENTIK_BOOTSTRAP_TOKEN`; fixed `AUTHENTIK_PORT=19000`). Create `data/` and copy `config/plugins.txt`.
2. `docker compose up -d --wait db cache mailpit authentik-db authentik-server authentik-worker`; wait for Authentik readiness (reuse `wait_ready`).
3. Run `authentik/bootstrap.py`; render `data/config.yaml`.
4. `docker compose up -d --wait inventree-server inventree-worker proxy`.
5. Install `django_slowtests==1.1.1` in the server container if the entrypoint did not; run `configure_inventree.py`; load demo data once.
6. Print: URLs (`http://localhost:8080`, Authentik admin `http://authentik.localtest.me:19000` with `akadmin` / bootstrap password, Mailpit), accounts, and the Claude Code command `claude mcp add --transport http inventree-dev http://localhost:8080/plugin/inventree-mcp/mcp/`.

`test.sh`: `docker compose exec -u root inventree-server bash -lc 'cd /home/inventree/src/backend && INVENTREE_PLUGIN_TESTING=True INVENTREE_PLUGIN_TESTING_SETUP=True python InvenTree/manage.py test "$LABEL" --keepdb "$@"'` (mirror the env the CI sets; `--keepdb` so repeated runs are fast). Must exit non-zero on failure.

## Acceptance (prove each in your report with the command and the relevant output lines)

1. `dev/up.sh` from a clean state finishes without manual steps (except a possible `/etc/hosts` line, which it must detect and explain).
2. `curl -s http://localhost:8080/api/` answers; `curl -s -u admin:admin http://localhost:8080/api/part/?limit=1` returns demo parts.
3. The plugin is active: `curl -s -u admin:admin http://localhost:8080/api/plugins/?active=true` lists `inventree-mcp`; `curl -s http://localhost:8080/plugin/inventree-mcp/mcp/` (no auth) returns the plugin's 401 JSON-RPC body, and `curl -s -H 'Authorization: Token <token>' -H 'Accept: application/json, text/event-stream' -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' http://localhost:8080/plugin/inventree-mcp/mcp/` lists tools (create the token via `POST /api/user/token/` with basic auth).
4. `dev/test.sh inventree_mcp.test_mcp` passes the upstream suite (report the summary line).
5. SSO works: `curl -s http://localhost:8080/api/auth/v1/config` (allauth headless config) lists the `authentik` provider; and a scripted login proves the round trip: adapt KINA's `run_flow`/`Browser` helpers into `dev/authentik/sso_smoke.py` that starts the allauth login (`POST /api/auth/v1/auth/provider/redirect` with `provider=authentik`, `process=login`, `callback_url=http://localhost:8080/web/logged-in`, with the CSRF cookie), follows the redirect into Authentik, drives the identification + password stages for `e2e-member`, follows back to InvenTree, and finally calls `GET /api/user/me/` with the session cookie. Expected: user `e2e-member` exists, is in InvenTree groups `Users` and `MCP Users`, and `socialaccount_socialtoken` holds a non-empty `token_secret` (refresh token) for it. Same script with `e2e-nonmember` must be refused by Authentik, and `e2e-guest` must log in but be in no InvenTree group.
6. `dev/down.sh` stops everything; `dev/down.sh -v` leaves no volumes or `data/` behind.

## Out of scope

No plugin code changes except `.gitignore`. No HTTPS (Claude Code accepts `http://localhost`). Do not modify the user's host Caddy; the proxy is the `caddy:alpine` container. Do not publish anything on port 5432, 80 or 443.
